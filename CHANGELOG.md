# Changelog of neocarta library and MCP server


## v0.9.0

### Added
- **Merge / idempotency & sparse-row contract** (`neocarta.ingest.utils`, GUIDE §5): GUIDE **D10**'s one-line non-clobber promise — *"partial data never erases fuller data"* — becomes an executable, tested specification, so multiple connectors (and multiple runs of one connector) can contribute to the same entity without losing each other's work (S1.3). `query_log` knows a column's `name`; `bigquery/schema` knows its `type`, `description` and key flags; both address the same `:Column`, and the contract now states — and proves — that neither loses the other's work and neither depends on running first: a write is **non-clobber** (a property the incoming row does not carry never replaces a stored value), **idempotent** (re-emitting a written row changes nothing) and **order-independent** (complementary sparse and full rows converge on the same entity in either feed order). The contract has **two layers**, because "does not carry" has two meanings: *property scope* — the source has no such concept, so the property gets no `SET` clause at all (the caller's existing `properties_list`, already validated against the model by `_validate_properties_list`) — and *value coalescing* — the source has the concept but no value for this row, so `n.p = coalesce(row.p, n.p)`. Neither layer suffices alone, and the reason is concrete rather than theoretical: `Column.nullable` is a bare `bool` defaulting to `True`, so a producer that knows nothing about nullability emits a non-`NULL` `True` that `coalesce` waves straight through onto a stored `False` — only the scope layer keeps that row honest, which is exactly why the S1.1/S1.2 normalized models default `is_primary_key`/`is_foreign_key` to `None` rather than a fabricated `False` (a tri-state field is protected by coalescing on its own, a two-state field is not); conversely scope is per *write*, not per *row*, so `connectors/jdbc`'s allowlist — which admits `description` if **any** column in the batch has one — leaves the rest of that batch relying on coalescing. **The S1.3 latitude call is that the writer enforces the merge and the normalized model declares only value semantics**, for four reasons: non-clobber is a property of a write against prior state, not of a row, so a Pydantic model (which cannot see the stored value) could only carry an annotation the writer must then act on — two owners of one piece of state, against GUIDE §4; the normalized contract is deliberately graph-agnostic (GUIDE D6), its guards rejecting graph identity on a field and requiring every annotation to stay a bare scalar, so a graph-write concern declared there would re-couple the contract to the ontology it exists to decouple from; the model→writer channel already exists as `properties_list`, so nothing new is needed to express which properties a source speaks about; and `_build_node_ingest_query`/`_build_relationship_ingest_query` are already the single **shared** place write semantics are decided (seven hand-written statements sit outside them, all of them policy-invariant), so S5 inherits the policy by moving the module (`ingest/` → `etl/pipeline` + generic writer, GUIDE §5). Mechanically, a new `MergePolicy` enum (exported from `neocarta.ingest`) replaces the builders' `overwrite_existing` boolean with the three policies that partition "what happens on a `MERGE` that matched" — `CREATE_ONLY` (properties fire `ON CREATE` only; first writer wins), `OVERWRITE` (every property written, `NULL` included) and `COALESCE` (the D10 contract; non-`NULL` values written, `NULL` skipped) — with the legacy boolean still accepted in the same argument slot, so **every existing call site keeps byte-identical Cypher** and both #291 Layer-B graph goldens plus the pinned-Cypher unit tests stay green (parity, GUIDE §2). The legacy flag is resolved by **truthiness** rather than a strict `bool` check, deliberately: the parameter was annotated `bool` but in practice accepted anything truthy, and since connectors read pandas frames a `numpy.bool_` (which is *not* a `bool` subclass) has to keep behaving exactly as it did — widening the argument must not narrow what it tolerates. A **string**, by contrast, is treated strictly as a policy name, so a misspelled `"coalesc"` raises `ConfigError` rather than falling through to the truthy branch and silently selecting destructive `OVERWRITE`. `COALESCE` is never destructive (`coalesce(NULL, 'x')` rewrites the stored value unchanged; `coalesce(NULL, NULL)` leaves an already-absent property absent, since Neo4j drops a property set to `NULL`, giving the same "omit undefined props" outcome the connectors hand-roll today) and applies secondary labels on every merge, as `OVERWRITE` does, because adding a label cannot lose information. The **parity characterization** the contract had to be reconciled against is now a test rather than an assumption, and it found a real gap: today's shipped `CREATE_ONLY` default satisfies non-clobber only *degenerately*, by never updating anything, and fails order-independence — fed full-then-sparse the fuller row survives, but fed **sparse-then-full the fuller row's `type`, `description` and key flags never land at all**, permanently, because properties fire only `ON CREATE`. That order is not hypothetical (every `examples/*query_log*` script runs a logs connector alone, so any schema ingest following one hits it), and it is reproduced end to end on real data by two runs of the production `CSVConnector` over the shipped `datasets/csv`, and it is the whole delta `COALESCE` closes; the before-picture is pinned as a passing characterization test since the legacy default is unchanged. **Three limits are documented rather than papered over**: two sources asserting *different* non-`NULL` values for one property resolve last-write-wins, because D10 is about loss and not disagreement and arbitrating conflicting authorities is a provenance question with no source of truth at this layer (order-independence is claimed for *complementary* rows only); the empty string is a value and not an absence, so `coalesce("", n.p)` is `""` and a source emitting blank descriptions clobbers real ones — decided at the model layer where `coerce_str_or_none` keeps `""` on purpose, a GUIDE D7 coercion question rather than a writer one; and relationship endpoints are still `MATCH`ed rather than `MERGE`d, so a row whose endpoints do not exist yet is silently dropped, a load-ordering property of the current writer left unchanged and outside D10. Two S5-facing hazards the sweep surfaced are enumerated in the contract rather than left implicit: **`load_osi_column_nodes`** is the one shipped loader that both fabricates key flags (`is_primary_key`/`is_foreign_key` as a hard `True`/`False`, never `None`) *and* writes them, onto the same `:Column` a tabular connector asserts them on — and because OSI is the graph/semantic paradigm (GUIDE D11) the normalized models' `None` defaults can never reach it, so it needs its own fix before the flip; and **`COALESCE` makes a property mutable after create**, which invalidates the embedder's `embedding IS NULL` fetch gate — sound only while a stored `description` cannot change — so S5 must ship embedding invalidation alongside the default flip or the vector and full-text tiers will disagree. Both are latent today (no shipped call site uses `COALESCE`) and both were reproduced live. **Additive and behavior-neutral**: `COALESCE` ships opt-in on the writer primitive, no connector's emitted Cypher changes, and no node type, relationship type or property is added to the graph model; connectors flip to the normalized contract in S4 and the generic writer adopts `COALESCE` as its default in S5, which is also where the `Column.is_primary_key` `False`→`None` reconciliation the `normalized_schema` README already lists comes due, since it is precisely the tri-state coalescing needs. Documented in a new `docs/refactor/merge-contract.md`, which GUIDE D10 and the `normalized_schema` README now both point at. Covered by unit tests pinning the generated statement per policy (plus legacy-bool parity across every property-count and secondary-label combination, and negative controls asserting `CREATE_ONLY`/`OVERWRITE` do **not** coalesce) and by graph-level integration tests that feed the real sparse/full `:Column` seam through a Neo4j testcontainer and assert order-independence as **whole-graph equality** via the #291 harness's `dump_graph` — stronger than per-property reads, since a stray extra node or edge fails too — with sensitivity verified per the harness's reference pattern by degenerating `COALESCE` to each of the other two policies and confirming both breaks go red at both layers. (#294)
- **Optional-facet models** (`neocarta.etl.metadata_normalizer.normalized_schema`, GUIDE §5): the **independently omittable facets** that hang off the S1.1 structural core — **values**, **references**, **lineage**, **glossary** and **governance** — so a connector emits only what its source actually exposes and a connector emitting only the structural core validates unchanged (S1.2). Eight new Pydantic v2 row models in a new `facets.py` — `ValueRecord`, `GlossaryRecord` / `CategoryRecord` / `BusinessTermRecord` / `BusinessTermAssignmentRecord`, `GovernanceTagKeyRecord` / `GovernanceTagValueRecord`, and `LineageRecord` — each surfacing as a `default_factory=list` table on `NormalizedStructuralSchema`, which stays the single public output (GUIDE D5) and the single owner of the emitted state (GUIDE §4); omittability is structural, so there is nothing to switch off. The shared field vocabulary moves to a new `_vocabulary.py` so the core and the facets cannot drift apart pending #296 ratification. Like the core, the facets are **natural-key-addressed** and **identity-agnostic** (GUIDE D6) — and, new here, carry **no graph label**: where the graph's polymorphic `TAGGED_WITH` uses a `source_label` + `source_id` pair, a facet row addresses its asset by an unbroken *prefix* of the natural-key path and the grain follows from the deepest populated segment, keeping ontology vocabulary out of the contract that exists to decouple connectors from the ontology (GUIDE §6). Because `column_name` is the only optional segment, prefix-closure is a **type-level** guarantee — a column-grain row always carries its table path and a gapped path is unrepresentable rather than merely rejected — and Table/Column are exactly the grains a tabular producer emits today (the Schema and Metric grains the graph also allows come only from the OSI paradigm, GUIDE D11; widening the path later is additive). The derivability rule that kept containment out of S1.1 removes five id-based facet edges entirely: `HAS_VALUE`, `HAS_CATEGORY`, `HAS_BUSINESS_TERM` and `HAS_VALUE_OPTION` are each a key path and one of its own prefixes, and `HAS_DEFINITION` is the natural-key join of an assignment against the tag-value table — set membership *is* the graph's semantics, since an applied value with no matching definition is free-form — so only the cross-hierarchy `TAGGED_WITH` and lineage edges are tables. The glossary facet reuses S1.1's identity/display split at every level, which is what lets one record serve CSV (which keys by name and carries a bare `name` label-override column), Dataplex (whose identity is a slug while its `*_name` columns are *labels* and its resource path is a separate locator) and OSI's synonym-derived terms; carrying the label as a first-class field also preserves the cross-connector business-term collapse, since `display_name or term_name` reproduces the name-keyed merge for all three. Dataplex's `glossary_id` / `category_id` / `term_id` columns are deliberately **not** aliased onto the identity fields: `AliasChoices` resolves to the first alias *present*, so absorbing them would silently bind the display label as identity — the connector pre-folds the slug instead, exactly as it must already pre-fold `column_mode`. Two new shared validators (added to `data_model/_validators.py`, the single validator owner) cover the two ways a key segment can go wrong (GUIDE D7 + D10): `coerce_str_required` casts a numeric cell to `str` but leaves NaN for Pydantic to reject, because a sampled value is a key segment whose id content-hashes it and a fabricated `""` would mint a real graph node for absent data; and `coerce_key_segment_or_none` folds a blank *optional* key segment to `None`, because an empty string is falsy yet is not `None`, so leaving it intact would let one consumer read a row as table-grain and another as column-grain — only blank folds, a real name is never stripped. Governance tag values go further and stay **uncoerced** so `High Risk` / `high-risk` / `high_risk` remain distinct as the content-hashed id requires. **What it deliberately does not do**: no `Transform` reification for lineage (minting that node and choosing its key is an identity decision the ontology makes downstream, GUIDE D6), no governance *instance/assignment* layer (a complete loader and Neo4j constraints exist but **zero** producers, so there is no source to normalize), no value sampling statistics (no producer computes any), no `description` on the tag-value record (the only producer sets it to `None` unconditionally), no nested glossary categories (Dataplex can nest them but its connector keeps only the innermost slug, so the parent link is lost upstream), and no FK `constraint_name`/`ordinal_position` (source-available but with nowhere to land, and composite grouping is already recoverable) — each additive when its producer lands. `ForeignKeyRecord` is unchanged and stays in the structural core: a foreign key is a declared structural constraint that a core-only connector emits, and its `foreign_keys` table was already omittable, so the references facet needed no new record. Keeps a Neo4j-native Graph Spec `sources → targets` expression open (GUIDE D14) — every table stays flat, and a facet table whose rows imply a relationship becomes a relationship target keyed on the natural-key columns the row already carries, with no graph ids and no `source_label`. **Contract-only, as S1.1 was** — no runtime path uses these models, and **no node type, relationship type or property is added to the graph data model**: `enums.py`, `data_model/` (beyond the two shared validators), `ingest/`, the Neo4j constraints, every connector `transform.py` and every MCP tool are untouched. Connectors flip in S4, proven at parity against the #291 characterization harness. Every synonym absorbed is a name some connector or shipped dataset actually emits — never one invented from plausibility — which a `test_no_invented_aliases` guard now enforces across every record the package exports, core and facet alike. Covered by model-level unit tests over every facet producer's real audited column names, with the contract-wide D6 no-`id`/no-`_id`/no-`embedding`/no-`source_label` guards extended to all fourteen models and self-maintaining against future additions. (#293)
- **Normalized structural-core models** (`neocarta.etl.metadata_normalizer.normalized_schema`, GUIDE §5): the flat, standardized, natural-key-addressed **tabular contract** every schema connector will emit — the source-agnostic substrate that decouples connectors from the ontology (S1.1). Five Pydantic v2 row models — `DatabaseRecord` / `SchemaRecord` / `TableRecord` / `ColumnRecord` / `ForeignKeyRecord` — plus a `NormalizedStructuralSchema` bundle (a connector's only public output, GUIDE D5). The models resolve the field-vocabulary divergence the audit found across the seven schema connectors — the ×4 container name (`project_id` / `table_catalog` / `catalog_name` / `database` / `catalog` / `database_name`), ×4 data type (`data_type` / `column_data_type` / `type` / `column_type`), and ×3 nullability (`is_nullable` / `column_mode` / `nullable`) — onto one canonical token per concept: each divergent field accepts its known source synonyms via `pydantic.AliasChoices` (canonical token first, so it stays the public field name and a spin-out connector can always emit canonical names, GUIDE D17), so a connector's **raw** source row validates directly. **Source-derived fields only** — no graph IDs and no embeddings (GUIDE D6); identity is assigned downstream by the KeySpec-driven ID builder from the raw key segments each row carries, and the `generate_id` logic is not replicated. Containment edges (`HAS_SCHEMA` / `HAS_TABLE` / `HAS_COLUMN`) are **derived** from the natural-key hierarchy rather than modelled as tables; only the non-derivable cross-hierarchy foreign-key reference is a table (`ForeignKeyRecord`, with role-scoped aliases so a connector's `table_*`-vs-`referenced_*` / shared-`constraint_*` FK frames all resolve source and target distinctly). **Value coercions, not just renames** (GUIDE D7): a new `coerce_nullable` validator (added to `data_model/_validators.py`, the single validator owner) folds the standardized nullability vocabulary (`YES`/`NO`, `NULLABLE`/`REQUIRED`, native bools) while source-specific fallbacks stay in the connector; `description`/`data_type` scrub NaN→None and `platform`/`service` upper-case. Sparse-row semantics (GUIDE D10): `is_primary_key`/`is_foreign_key` default to `None` (unknown) rather than a fabricated `False`, while `nullable` keeps the permissive `True` default matching the graph model. The contract is documented (canonical vocabulary + a Graph Spec `sources` mapping sketch that keeps a Neo4j-native import-spec expression open, GUIDE D14) in the package `README.md`. **Contract-only** — no runtime path uses it yet; connectors flip to it in S4, proven at parity against the #291 characterization harness. Covered by model-level unit tests proving each connector's raw source field-set maps onto the core without loss. (#292)

### Fixed
- The #290 coverage / test-count regression gate (`make check-regression`) is no longer red in CI. Its full-tree `pytest --collect-only tests` imports the MCP server integration modules, which build the module-level `mcp_server_settings = Settings()` singleton (`neocarta/_mcp/settings.py`) at import — requiring `NEO4J_URI` / `NEO4J_USERNAME` / `NEO4J_PASSWORD`. The `coverage` CI job provides no `.env` and no `NEO4J_*` env, so those two modules raised a `ValidationError` at collection and dropped out of the suite, pushing the collected count below the `all` baseline and failing the gate. `tests/integration/_mcp/conftest.py` now seeds inert defaults for those vars at import (after honoring a real `.env` via `load_dotenv`, so a configured environment is unaffected), keeping the package collectable in a bare env. Test-infra only, no behavior change (GUIDE 0.8.1). (#290)
- `DatabricksSchemaExtractor.extract_column_unique_values_for_table` no longer accumulates duplicate sampled values in its cache when called more than once for the same table with `cache=True`; the cached values frame is now de-duplicated by `value_id`, so repeated calls can't produce duplicate `:Value` nodes / `HAS_VALUE` edges. It also now warns when no column metadata is available (so non-sampleable complex types can't be detected), instead of silently pushing a complex column into a `collect_set` query that Databricks would reject.
- `DatabricksSchemaExtractor` now rejects a `catalog` containing a backtick at construction (a `ConfigError`), matching the up-front `schema` validation, instead of only failing when the first query reaches identifier-quoting.
- `DatabricksSchemaTransformer.transform_to_references_relationships` no longer re-filters on `constraint_type == "FOREIGN KEY"` (the extractor already emits foreign-key rows exclusively); the redundant filter was also a latent `KeyError` on a column-less empty frame. It now iterates the references frame directly and tolerates an empty frame that carries no `constraint_type` column.
- `write_embeddings_to_graph` now logs the actual number of embeddings written based on input row count, instead of `summary.counters.properties_set`, which is always 0 because `db.create.setNodeVectorProperty` is a procedure call and Neo4j query summary counters do not track procedure-call writes. (#216)
- Connector skills now document search-entry-point index requirements and embedding label obligations. Any node label used as an MCP search entry point must have a full-text index created at load time and must be included in the CLI `--embeddings` label set. Override hazard for `Neo4jRDBMSLoader` subclasses is now explicit in the contract. (#211)

- `SnowflakeSchemaConnector` and `SnowflakeLogsConnector` (`neocarta.connectors.snowflake`) plus the `neocarta snowflake schema` / `neocarta snowflake logs` CLI verbs: a Snowflake source-connector family modeled on the BigQuery/Databricks connectors, read through the official pure-Python `snowflake-connector-python` (DB-API 2.0) — **no Spark, no JDBC** — pulling results into pandas with `cursor.fetch_pandas_all()`. **Schema** ingests structural metadata (`Database`, `Schema`, `Table`, `Column`, `Value` nodes plus `HAS_SCHEMA` / `HAS_TABLE` / `HAS_COLUMN` / `HAS_VALUE` / `REFERENCES` edges) from a database's `<database>.INFORMATION_SCHEMA.*` views (`extract` → `transform` → `load` → `upsert_neocarta_graph_node`, `StateError` on out-of-order calls). A Snowflake database maps to `Database` (analog of the BigQuery project, a constructor arg, `platform="SNOWFLAKE"` / `service="SNOWFLAKE"`), a schema to `Schema` (passed per `ingest(schema=...)` call — one schema per call), tables and views to `Table`, and columns to `Column`. Because Snowflake's `INFORMATION_SCHEMA` has no `KEY_COLUMN_USAGE` view, primary/foreign-key *columns* are read from `SHOW PRIMARY KEYS` / `SHOW IMPORTED KEYS` (keys are informational, not enforced) to set the column key flags and produce `REFERENCES` edges; cross-database foreign keys are dropped with a warning. Sample distinct column values (`:Value` / `HAS_VALUE`) are read on by default via a bounded `SELECT DISTINCT TO_VARCHAR("col") … ORDER BY 1 LIMIT n` per groupable column — UNION ALL-batched into a few statements (`value_sample_query_batch_size`, default 50) so a wide table costs a handful of round trips, not one per column (the cap is pushed into the scan rather than materialising the full distinct set; `ORDER BY` makes the sampled subset deterministic so re-ingests are stable; the value is stringified server-side so a large `NUMBER` id keeps full precision and out-of-range timestamps can't overflow the pandas fetch) and skip non-groupable types (VARIANT/OBJECT/ARRAY/MAP/GEOGRAPHY/GEOMETRY/VECTOR — e.g. a `VECTOR` embedding column, which Snowflake refuses to `SELECT DISTINCT`); because that is the only stage that reads table *data* (warehouse cost / data-read grants / PII), it can be disabled with `value_sample_limit=0`. **Logs** parses `SNOWFLAKE.ACCOUNT_USAGE.QUERY_HISTORY` (skipping rows with NULL/blank `QUERY_TEXT`, which `ACCOUNT_USAGE` may return for redacted/uncaptured statements) into `Query` / `CTE` nodes and `USES_TABLE` / `USES_COLUMN` / `DEFINES` edges, reusing the shared `QueryLogTransformer` and adding a `read="snowflake"` branch to `parse_sql_query` (platform/service `SNOWFLAKE`). Caller-supplied identifiers (`database` / `schema`) are resolved the way Snowflake resolves identifiers — an unquoted name is folded to upper-case (so `analytics` finds the stored `ANALYTICS`) and a double-quoted name is a case-sensitive literal — then double-quoted for interpolation (embedded quotes doubled); ids normalize via `connectors/utils/generate_id.py`. The caller constructs and owns the `snowflake.connector` connection (mirroring how the BigQuery connector takes a `client`), so `close()` is a no-op and never closes it; the CLI builds and owns the connection it passes, authenticating via key-pair (`SNOWFLAKE_PRIVATE_KEY_PATH` [+ `SNOWFLAKE_PRIVATE_KEY_PASSPHRASE`]), an authenticator (`SNOWFLAKE_AUTHENTICATOR` + optional `SNOWFLAKE_TOKEN`, e.g. externalbrowser / oauth / programmatic-access-token), or password (`SNOWFLAKE_PASSWORD`) — key-pair is the path for MFA-enforced accounts, where Snowflake blocks programmatic password auth; when more than one method is set the highest-precedence one wins (key-pair > authenticator > password) and the others are never transmitted. `snowflake.connector` exceptions are mapped to typed neocarta errors by `snowflake/_errors.py`, classified by exception **class** only (a `ProgrammingError` → `ConfigError`, transient operational/internal errors → a `retryable` `ExtractionError`), never by message text. Ships behind the optional `snowflake` extra (`pip install neocarta[snowflake]`, which pulls `snowflake-connector-python[pandas]`); the package imports without the extra (lazy/`TYPE_CHECKING` imports) and the CLI fails with a clean `usage_error` + install hint when it is missing. Runnable examples live in [`examples/snowflake_schema.py`](examples/snowflake_schema.py) and [`examples/snowflake_query_log.py`](examples/snowflake_query_log.py). Covered by mocked-connection unit tests (conformance + extract + transform + logging + CLI); a live-warehouse integration test is intentionally excluded from CI, so the extraction SQL is validated manually against a live warehouse. The Snowflake and Databricks schema connectors now share the RDBMS transform, Extract→Transform→Load lifecycle, and DB-API error-mapping scaffolding via `neocarta.connectors.utils` (`RdbmsSchemaTransformer` / `RdbmsSchemaConnector` / `dbapi_errors`); only source-specific extraction SQL stays per-connector.

- **Governance-tag data model** (`neocarta.data_model.governance`): a new, vendor-neutral component for modelling governance tags (controlled-vocabulary labels used for policy/classification/ownership) in their own right, rather than forcing them into the business glossary (`Glossary` / `Category` / `BusinessTerm`), where a tag's values are not business *terms*.
